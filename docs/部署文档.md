# RentAI Docker 部署文档

> 作者：zcy。三容器一键部署：`postgres(pgvector)` + `redis` + `backend(uvicorn@8000)`，前端由 backend 静态托管或独立 dev server。

---

## 前置条件

- 已安装 **Docker Desktop** 并启动（引擎就绪约需 10~20 秒）
- 已准备阿里云百炼 / 高德开放平台的 API Key

## 一、配置密钥

```bash
cp backend/.env.example backend/.env   # 填入你自己的 key（绝不提交真实 key）
```

必填变量：

| 变量 | 说明 |
|---|---|
| `DASHSCOPE_API_KEY` | 阿里云百炼 API Key（`sk-` 开头） |
| `DASHSCOPE_BASE_URL` | 百炼 OpenAI 兼容网关地址 |
| `CHAT_MODEL` / `EMBEDDING_MODEL` / `RERANK_MODEL` | qwen-plus / text-embedding-v4 / gte-rerank |
| `AMAP_KEY` | 高德开放平台 Web 服务 Key |

## 二、一键启动

```bash
docker compose up -d
```

| 服务 | 容器 | 端口 | 用途 |
|---|---|---|---|
| PostgreSQL + pgvector | `rentai-postgres` | 5432 | 房源向量 / 文档块 / 看房清单 |
| Redis | `rentai-redis` | 6379 | 会话记忆 / 用户画像 / 缓存 |
| 后端 API | `rentai-backend` | 8000 | FastAPI + Agent |

- 前端页面：`http://localhost:5173`（前端 dev server 独立启动时）
- 后端 API：`http://localhost:8000`

## 三、常用命令

```bash
# 启动 / 停止 / 查看状态
docker compose up -d
docker compose down            # 停止（保留数据卷）
docker compose down -v         # 停止并清空数据卷

# 重建后端（代码或 Dockerfile 变更后）
docker compose build backend && docker compose up -d backend

# 日志与健康检查
docker compose logs -f backend
docker compose ps
curl http://localhost:8000/health          # 若有健康端点
curl http://localhost:8000/api/rent/observe/metrics   # 观测/评测指标
```

## 四、数据持久化

- 业务数据落在 **命名卷**（`pgdata` / `redisdata`），`docker compose down` 不清空，`down -v` 才清空。
- `backend/.env` 为本地密钥文件，**已被 `.gitignore` 排除**，不进仓库。

## 五、本地开发（无 Docker）

```bash
# 后端
cd backend && uv sync && uv run uvicorn app.main:app --reload --port 8000
# 前端
cd frontend && npm install && npm run dev
```

## 六、常见问题（FAQ）

| 问题 | 处理 |
|---|---|
| 端口 8000 / 5432 被占用 | 先停占用进程，或改 `docker-compose.yml` 端口映射 |
| 容器启动后接口报错 | `docker compose logs -f backend` 看日志；多半是 `.env` 缺失/填错 |
| 改了后端代码不生效 | 需重建镜像：`docker compose build backend && up -d backend` |
| 评测/观测无数据 | 确认对话式 Agent 至少跑过一轮（用量随响应累计）；语义评测较慢（调 LLM，独立子进程执行） |
